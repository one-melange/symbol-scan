# SymbolScan — Tasks

Standing backlog for SymbolScan. This is the single source of truth for what's planned,
in progress, and done.

## Convention

- Sections by horizon: **Now** (actively being worked), **Next** (queued), **Later**
  (someday/maybe), **Done** (shipped).
- One line per item: `- [ ] (Txx) Short title — one-line why · file:line`
- When an item ships, check it off and move it to **Done** with the commit/PR ref.
- IDs (`Txx`) are stable — don't renumber. New items get the next free number.
- `(verified)` = confirmed against source. `(reported)` = surfaced by audit, line refs
  not yet verified.

- [x] (T22) `Indexer.buildIndex` testability seam + `IndexerTests` — the scan → parse → dedup → cache composition had no test (deferred by T19). The seam turned out to be **one defaulted parameter**, not protocol injection: `IndexCache.save`/`load` already took an injectable `base:`, `Indexer` just never forwarded it, so the only untestable dependency was the cache write landing in the user's real Application Support dir. `buildIndex(root:cacheBase:)`/`loadCache(root:cacheBase:)` now forward it; the default is evaluated per call site, so both production call sites still pass `(root:)` and behave identically. Tests run against a **real temp git repo** with real grammars and real IO on purpose — mocking the scanner would only re-test units that are already covered, and it was precisely a whole-pipeline run that exposed the T8 minified-bundle bug when every individual unit was behaving correctly. 12 tests: per-dialect symbols in one pass, Go receiver signature survival, repo-relative paths (T2), the minified bundle yielding no code symbols but keeping its `.file` entry, T18 file/dir entries, the documented code-symbols-before-paths ordering, `fileCount` counting source files only, dedup, cache round-trip landing **only** in the injected base, `notGitRepo`, and cancellation. `makeTempDir`/`runGit` hoisted out of `RepoScannerTests` into a shared `TestSupport.swift` (third user). All verified by mutation — dropping the `cacheBase` forwarding, the `isMinified` guard, or the append ordering each turns the suite red · `SymbolScan/SymbolScan/Index/Indexer.swift`, `SymbolScanTests/IndexerTests.swift`, `SymbolScanTests/TestSupport.swift` · branch `multi_lang`
- [x] (T8) Language coverage — JS/JSX closed. `.js`/`.jsx`/`.mjs`/`.cjs` now index via a new `.javascript` dialect backed by `tree-sitter-javascript` (exact 0.23.1, matching the sibling grammars' vintage). `.jsx` needs no separate grammar — unlike TS/TSX, the JavaScript grammar parses JSX natively. The JS query is deliberately **not** a copy of the TS one: JS names classes with `(identifier)` where TS uses `(type_identifier)`, and has no `interface_declaration`/`type_alias_declaration`/`abstract_class_declaration`, so a copied query would fail to compile and (post-T21) silently zero out every `.js` file. Minified/generated JS is screened out in two layers, because `git ls-files` doesn't honour `RepoScanner.excludedDirs`: a cheap name check (`*.min.js`, `*.bundle.js`) in `Language.detect` that avoids the read entirely, and — since name patterns miss the common case, Vite emits `index-DJ7HgGZS.js` — a `SymbolParser.isMinified` content check that skips any source whose longest line exceeds 5,000 characters. Verified against a real repo: two committed 4.9 MB Vite bundles were contributing **16,901** junk symbols (`ur`, `Rr`, `Sm`, …); measured across 174 real files, hand-written code topped out at 1,289 chars/line vs 628,095 for minified, so the threshold isn't delicate. A general file-size cap is still T7. `project.pbxproj` needed the package in **all five** sections (`PBXBuildFile`, frameworks phase, target `packageProductDependencies`, project `packageReferences`, and the two `XC*` blocks); the middle two are the easy ones to miss and fail differently · `SymbolScan/SymbolScan/Index/TreeSitterParser.swift`, `Index/Symbol.swift` + build · branch `multi_lang`
- [x] (T20) `.tsx` parsed with the TSX grammar — `.tsx` was routed to `Language.typescript`, whose grammar can't parse JSX. Tree-sitter error-recovers rather than failing, so no fallback ever fired and symbols in every `.tsx` file silently vanished from the index (pinned by `jsxUnderThePlainTypeScriptGrammarLosesSymbols`). Added a `.tsx` dialect mapped to `tree_sitter_tsx()`. **No project-file change was needed**: `TreeSitterTSX` is a second *target* inside the already-linked `TreeSitterTypeScript` *product*, so `import TreeSitterTSX` just works (adding an `XCSwiftPackageProductDependency` for it would be invalid — no such product). TSX names every node/field we match identically to TypeScript, so the query text is shared but compiled/cached separately (a `Query` is bound to a `TSLanguage`). `Language` is now documented as the **grammar key**, not a language name — nothing renders or persists it (`Symbol` has no language field), so raw values are free to change; dead `FileEntry` and `Language.extensions` deleted. `IndexCache.version` 3→4 so tsx-symbol-free caches aren't served forever · `SymbolScan/SymbolScan/Index/TreeSitterParser.swift`, `Index/Symbol.swift`, `Index/SymbolIndex.swift` · branch `multi_lang`
- [x] (T21) Removed the dead `RegexParser` fallback — `TreeSitterParser.parse` returns nil only when a grammar or query fails to *build*, which is deterministic and cached-on-success, and tree-sitter error-recovers so a broken source file yields `[]` not nil. The fallback was therefore unreachable in production: deleted `Index/RegexParser.swift` (201 lines) + `RegexParserTests.swift` (124). `SymbolParser.parse` is now non-optional and reports a grammar-build failure **once per language** — silently returning `[]` is exactly how T20 went unnoticed. `TreeSitterParser.parse` stays optional: it's the `try #require` test seam and the only signal separating "broken grammar" from "no declarations". The one capability regex had that Tree-sitter didn't — `Symbol.signature`, still rendered by `SymbolPickerView` — was reimplemented for Go methods from `method_declaration`'s `receiver` field, so `(*Server) Close` and `(Conn) Close` are distinguishable in the picker. New `everyDialectBuildsAGrammarAndQuery` test guards the now-fallback-free path · `SymbolScan/SymbolScan/Index/TreeSitterParser.swift` · branch `multi_lang`
- [x] (T19) Background / non-blocking indexing + multi-repo + completion notification — root cause of the large-repo freeze was a `Process`/`Pipe` deadlock in `RepoScanner.gitLsFilesRaw`: it called `waitUntilExit()` *before* draining stdout, so a repo whose `git ls-files` output exceeded the ~64KB pipe buffer (a large monorepo of tens of thousands of files, well over 1 MB of output) blocked git on a full pipe while the app blocked waiting for git — a hang that never completed. Fixed by reading stdout to EOF before waiting + discarding stderr to `nullDevice`. Indexing also moved off the `@MainActor` into a nonisolated `Indexer.buildIndex` (`Task.detached`); `SymbolIndex` now holds an active-repo view plus a per-repo background job registry (`jobs: [URL: Task]`) so repos index concurrently and switching never cancels another repo's job (publishes guarded by `indexedRepoRoot`). Real-scan completion posts a `UNUserNotificationCenter` banner (`IndexNotifier`) + live menu-bar tooltip; cache hits stay silent. `activateRepo`/`reindex` are synchronous non-blocking launchers; dead-repo cleanup via `SymbolIndex.onRepoInvalid`; removed the dead `reindexFile`/`scanner` (see T4). Regression test `RepoScannerTests.enumerateAllFilesDoesNotDeadlockOnLargeGitOutput` (real repo, >64KB output — hangs the run if the deadlock returns). **Verified live** on a large monorepo (tens of thousands of symbols, UI responsive).
